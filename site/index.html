We invented the car. Stop fitting tools to the horse.

AI agents are here. They can reason, plan, and act. But every browser automation tool still treats them like dumb scripts that need to be hand-held through the DOM.

Playwright was built in 2020 for test engineers writing deterministic scripts. Puppeteer was built for headless rendering. Selenium was built in 2004. None of them were built for AI. They were built for humans writing code that controls a browser. Now we're duct-taping AI onto tools designed for a completely different era.

The result? We make the smartest technology on the planet do the dumbest work — parse thousands of lines of <div class="css-1a2b3c">, guess fragile CSS selectors, stare at pixel screenshots trying to figure out where a button is. We're asking a race car to pull a plow.

The problem isn't the agent. It's the tools.

Every existing tool puts the hard job on the agent. Here's a page — figure out what's on it. Here's raw HTML — find the login button. Here's a screenshot — guess where to click. The agent has to be a frontend developer, a CSS expert, and a computer vision system just to fill out a form.

That's backwards. The tools should be AI-first. The browser should understand the page and explain it to the agent, not dump raw data and hope for the best. The agent shouldn't need a translation layer between "I want to click the search button" and the actual click.

Oya Browser is the browser built for agents

Instead of making the agent figure out what the page has, the browser tells the agent what it has. It walks the DOM, finds every interactive element, numbers each one, and returns a clean markdown description — the same way a human would describe a page to someone over the phone.

The agent reads: [#13 button "Google Search"]. It says: click(13). Done. No selectors. No HTML. No coordinates. No screenshots. No 600-line system prompt teaching the model how to navigate. No 13 watchdogs for crash recovery. No fragile translation layer between the AI and the browser.

The browser does the hard work so the agent doesn't have to. That's what AI-first tooling means.

How it works

Analyze → Read → Act

The user browses normally. The AI connects via MCP and controls the browser through simple tools.

1

analyze_page

Walks the DOM, finds every link, button, input, dropdown. Highlights each with a colored outline and assigns a number. Returns the full page as markdown.

2

Agent reads markdown

The AI gets structured text — headings, forms, landmarks — with elements annotated as [#9 input:search]. It understands the page instantly.

3

Act by number

type(9, "query") then click(13). The element IDs are real attributes on the DOM — querySelector resolves them instantly.

Key difference

IDs live on the actual DOM

When the AI says click(5), the browser runs querySelector('[data-ac-id="5"]'). One call. No translation.

Browser-use / Playwright

The AI gets an element index. To click, the framework resolves the index back to a CDP node ID, then dispatches a mouse event at computed coordinates. Six round-trips. If the DOM changed, it fails.

1. Look up index in serialized tree
2. Resolve to CDP backendNodeId
3. DOM.resolveNode → remote object
4. DOM.scrollIntoViewIfNeeded
5. DOM.getBoxModel → coordinates
6. Input.dispatchMouseEvent

Oya Browser

During analysis, the element was tagged with data-ac-id="5" directly on the HTML element. The number is a real attribute on the real DOM. One querySelector.

1. document.querySelector(
     '[data-ac-id="5"]'
   )
2. el.click()

Done.
Features

Chat, actions, network, source

The built-in dev panel gives you full control and visibility — talk to the browser in natural language, fire actions manually, watch traffic, and see the page as AI sees it.

Chat

Natural language browser control. "Go to google and search for cats" — the AI navigates, types, clicks, and reports back. Formatted responses with tool badges.

Actions

Quick-fire buttons for every command — analyze, screenshot, click by element #, type text, press keys, hover, scroll, navigate, tab management. No AI needed.

Network

Live WebSocket traffic between browser and server. Timestamped IN/OUT entries, expandable payloads, filter by direction or type.

Source

See the page as AI sees it — toggle between the structured markdown from analyze_page and raw HTML source. Refresh on demand.

Multi-tab browsing

Agents can open_tab, switch_tab, list_tabs, close_tab. Work across Gmail, Docs, and Jira simultaneously.

Live view

Server streams JPEG frames from the browser via SSE. Watch what the agent is doing in real-time from the dashboard.

Human-like input

All keyboard and mouse input via Chrome DevTools Protocol. Bézier curve mouse paths, 8-26ms typing delays, micro-hesitations. Indistinguishable from a real user.

Anonymity

Every session a different identity

Create profiles with unique fingerprints, proxy routing, and isolated cookie stores. Switch identities with a single MCP call.

Fingerprint rotation

Unique canvas, WebGL, audio, and font fingerprints per profile — deterministic and internally coherent per platform.

Stealth mode

Removes Electron markers, fixes window.chrome, navigator.webdriver, plugins, and permissions. Passes bot detection.

Proxy & DNS

SOCKS5/HTTP proxy per profile with DNS leak prevention and WebRTC protection. Timezone and locale auto-match proxy geo.

Telemetry blocked

Chromium phone-home domains blocked, Safe Browsing disabled, no background networking. Zero data leaks to Google.

# Docker docker run -d -p 3100:3100 -e API_KEYS=your-key ghcr.io/oyadotai/oya-browser-server # Or from source cd server && cp .env.example .env && npm install && npm start

2. Download Oya Browser

Oya Browser macOS · Linux

Desktop app with multi-tab browsing, dev panel, persistent cookies, and live view. Download, connect, browse.

1. Download for your OS
   macOS: Oya Browser.dmg
   Linux: Oya Browser.AppImage
2. Open → enter server URL + API key
3. Connected — start browsing

3. Connect your AI tool

Open http://your-server:3100 to see connected browsers and copy the MCP config.
