Browser for Agents

Existing browsers were built for humans. Every tool trying to make AI control them is duct-taping automation onto something that was never designed for it. Oya Browser is built from the ground up for AI agents.

Download Open Dashboard
The problem

AI agents can't use browsers. The tools are the bottleneck.

Playwright, Puppeteer, Selenium — they were built for human testers writing scripts, not for AI. When you connect an AI agent to these tools, it has to parse thousands of lines of raw HTML, guess CSS selectors like div.main > ul:nth-child(3) > li > a, or stare at pixel screenshots trying to figure out where a button is.

The agent spends more time fighting the browser than doing the actual task. Selectors break when sites update. Screenshots burn tokens and miss context. Every tool puts the hard work on the AI.

That's backwards. The browser should do the hard work — not the agent.

The solution

A browser that explains itself to the AI

Oya Browser analyzes the page, numbers every interactive element, and returns clean markdown — the same way a human would describe a page to someone over the phone. The agent reads [#13 button "Google Search"] and says click(13). Done.

No HTML parsing. No CSS selectors. No pixel coordinates. No screenshots. No 600-line system prompts teaching the model how to navigate. The element IDs are real attributes on the DOM — one querySelector and it clicks.

And because it's your real browser — your cookies, your logins, your sessions — there's no bot detection, no CAPTCHAs, no auth workarounds. The site trusts you because it's actually you.

How it works

Three steps

1

Download & connect

Download Oya Browser, open the dashboard to create an API key, then paste it in the browser to connect.

2

Browse normally

Log into your accounts, use your extensions, browse like you always do. The AI sees your real browser.

3

AI takes over

Connect Claude, Cursor, or any MCP client to the browser's MCP endpoint. The AI analyzes pages and acts by element number.

What the AI sees

Pages as numbered markdown — not HTML or pixels

When the AI calls analyze_page, the browser walks the DOM, numbers every interactive element, and returns structured markdown.

---
url: https://google.com
elements: 22 total, 22 visible
---

<!-- nav -->
[#1 link "About"]  [#3 link "Gmail"]

[#9 textarea placeholder="Search"]
[#13 button "Google Search"]
[#14 button "I'm Feeling Lucky"]

## Element Index
  [#9]  textarea: Search
  [#13] button: Google Search
  [#14] button: I'm Feeling Lucky
  [#3]  link: Gmail

The AI reads this, then says type(element_id=9, text="hello") and click(element_id=13). No selectors. No screenshots. Just the number.

For AI tools

Connect any MCP client

Get your browser's MCP endpoint from the dashboard and add it to your AI tool:

// Cursor, Claude Desktop, Windsurf, or any MCP client
{
  "mcpServers": {
    "oya-browser": {
      "url": "https://browser.oya.ai/mcp/YOUR_BROWSER_ID",
      "transport": "streamable-http",
      "headers": { "Authorization": "Bearer YOUR_API_KEY" }
    }
  }
}
Scale

Run 1,000 browsers as one pool

Set a single fleet token, point every browser at it, and they all join the same pool. The server round-robins commands across browsers and syncs cookies in real-time — so every browser has the same sessions, logins, and state.

Your AI client connects to one endpoint: /mcp/pool. No browser IDs, no per-instance config.

1

Set one fleet token

Add FLEET_TOKEN=secret to your server env. That's the only config.

2

Connect N browsers

Every browser uses the fleet token as its API key. They auto-join the pool and sync cookies.

3

One MCP endpoint

Point your AI at /mcp/pool. Commands rotate across browsers. Cookies stay in sync.

// AI client config — one pool endpoint for all browsers
{
  "mcpServers": {
    "oya-pool": {
      "url": "https://browser.oya.ai/mcp/pool",
      "transport": "streamable-http",
      "headers": { "Authorization": "Bearer YOUR_FLEET_TOKEN" }
    }
  }
}
